# История остатков и заказов Wildberries

## Права доступа

- Permission: `subscriber wb stock history`
- Middleware панели: `auth`, `verified`, `panel.access`, `wb.cabinets.migrated`, `permission:subscriber wb stock history`
- Кабинет: единый WB (`wb_cabinets` / `selected_wb_cabinet_id`) — см. [wb-cabinets.md](wb-cabinets.md)

## Назначение

Один инструмент с двумя вкладками:

1. **История остатков** — сколько товара было в разные дни и сколько сейчас в наличии / в пути. Первая загрузка — общие остатки по размеру, без разбивки по складам.
2. **История заказов** — сколько единиц товара заказали в каждый день.

Истории независимы: наличие дней в одной вкладке не означает наличие в другой.

## Сценарий

1. Открыть `/panel/wb/stock-history`, при необходимости выбрать кабинет в шапке.
2. На нужной вкладке нажать «Начать отслеживание». Дата не спрашивается: грузим последние два календарных месяца по сегодня. В модалке остатков: история по товарам и размерам, без складов, дальше дни пишутся сами.
3. После загрузки таблица показывает выбранный период. Незагруженные дни — прочерк, не ноль. Повторно историю не загружаем.
4. Каждый день после полуночи система дописывает вчерашний день, пока отслеживание включено.
5. «Остановить отслеживание» — новые дни не пишутся, история на экране остаётся. «Включить снова» — сбор продолжается без повторной загрузки.

По умолчанию на экране последние 30 дней по сегодня.

## Источники Wildberries

Даты — московский календарь.

| Данные | API | Ограничения |
|--------|-----|-------------|
| Текущие остатки по складам | `POST /api/analytics/v1/stocks-report/wb-warehouses` | `warehouseId` + `quantity`. Заглушка `-999999` не показываем |
| Справочник складов | `GET /api/v3/offices` | `id` → название (Коледино, Электросталь…). Категория Marketplace |
| История остатков | CSV `STOCK_HISTORY_DAILY_CSV` через `/api/v2/nm-report/downloads` | До 3 месяцев у WB, в UI 2 календарных месяца. Итог по размеру, без складов (`OfficeName` сейчас «Склад WB», колонки `warehouseId` нет) |
| Карточки | `POST /content/v2/get/cards/list` | Предмет, артикул продавца, размер, баркод |
| Заказы | `GET /api/v1/supplier/orders` | 90 дней, 1 строка = 1 единица, ключ `srid` |

Склады продавца (FBS) в первую версию не входят.

Воронка продаж для заказов не используется: JSON — максимум неделя и без размера/баркода, годовой CSV — только с подпиской «Джем».

### Как считаем заказ

- Дата — день оформления (`date`, МСК).
- Отменённый заказ (`isCancel`) всё равно считается: его оформили в этот день.
- Повтор строки с тем же `srid` не увеличивает счётчик.
- Возвраты не входят.
- Неоплаченные / рассрочка могут не прийти из API — это ограничение Wildberries.

## Схема БД

- `wb_stock_history_settings` — срок хранения и статусы вкладок
- `wb_stock_history_products` — справочник размеров
- `wb_stock_history_warehouses` — склады
- `wb_stock_history_days` / `wb_order_history_days` — какие даты реально загружены
- `wb_stock_history_items` — остаток на дату (пустых CSV-ячеек нет)
- `wb_order_history_items` — число заказов на дату

CSV пишет итог размера в ключ склада `_total`. Снимок `wb-warehouses` может записать текущие остатки по `warehouse_id`, но в UI первая история по складам не обещается. Страница внешние API не вызывает.

Срок хранения: по умолчанию 90 дней, минимум 7, максимум 180. Старые дни удаляет `subscriber:wb-stock-history-prune`.

## Web-маршруты

Prefix: `/panel/wb/stock-history` · name: `subscriber.wb.stock-history.*`

| Method | URL | Назначение |
|--------|-----|------------|
| GET | `/` | Workspace (`tab=stocks\|orders`) |
| GET | `/status` | JSON статуса загрузки |
| GET | `/stocks/{nmId}/{chrtId}` | JSON складов размера за период |
| POST | `/stocks/load` | Первая загрузка истории остатков (всегда два месяца по сегодня, включает отслеживание) |
| POST | `/stocks/refresh` | Служебный: перезаписать дни из отчёта WB. Из панели не вызывается |
| POST | `/stocks/start` | Включить отслеживание остатков |
| POST | `/stocks/stop` | Остановить отслеживание остатков |
| POST | `/orders/load` | Первая загрузка истории заказов (всегда два месяца по сегодня, включает отслеживание) |
| POST | `/orders/start` | Включить отслеживание заказов |
| POST | `/orders/stop` | Остановить отслеживание заказов |
| PUT | `/settings` | Срок хранения |

## Очередь

```
php artisan queue:work --queue=wb_stock_history --tries=2 --timeout=1800
```

| Job | Timeout | Unique |
|-----|---------|--------|
| `ProcessWbStockHistoryBackfillJob` | 1800 | кабинет |
| `ProcessWbStockHistorySnapshotJob` | 1800 | кабинет + дата |
| `ProcessWbOrderHistoryBackfillJob` | 1800 | кабинет |
| `ProcessWbOrderHistorySnapshotJob` | 1800 | кабинет + дата |

Расписание (МСК): снимок остатков 01:00, снимок заказов 01:20, prune 02:00. Только кабинеты с включённым сбором вкладки.

## UI

Страница: `resources/js/Pages/Subscriber/Wb/StockHistory/Index.vue`.

Вкладки сверху. Блок «История данных»: «Начать отслеживание» / «Включить снова» / «Остановить отслеживание». Первая загрузка — модалка без даты: всегда два месяца по сегодня. Тексты для пользователя — про пользу (соберём историю, будем обновлять автоматически), без «вчерашнего дня» и внутренней механики. После загрузки повторной загрузки нет. Сбор идёт в очереди, на экране панель статуса как у рентабельности.

Остатки — строка размера (фото без названия колонки). Раскрытие складов: в истории CSV разбивки нет. Общие остатки и «в пути» — из снимка `wb-warehouses`, если он есть. История размера — сумма CSV (`_total`).

Заказы — строка размер × баркод. Первая колонка — фото товара без названия. Загруженный день без заказов = 0, незагруженный = прочерк.

Строки можно отмечать. Внизу строится график по выбранным: каждая строка — отдельная линия, при двух и больше добавляется сумма. Незагруженный день на графике пропускается, не рисуется как ноль.

Тексты для пользователя — без технических названий API.
