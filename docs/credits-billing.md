# Кредиты (Credits Billing)

Единый баланс для оплаты AI-услуг платформы. В коде, БД и API сущность называется `credits`. В интерфейсе всегда **кредиты**.

Админка и кабинет работают только с кредитами. **AI-анализ кабинета WB/Ozon**, **ответы на отзывы Wildberries** и **AI Инструменты** (текст, изображения, видео) списывают кредиты. Колонки `limits_month` / `extra_limits_month` и таблица `extra_limits` удалены.

## Модель баланса

У пользователя один счёт `credit_accounts`:

| Поле | Смысл |
|------|--------|
| `subscription_balance` | Кредиты текущего периода тарифа |
| `purchased_balance` | Купленные кредиты (не сгорают) |
| `subscription_held` / `purchased_held` | Резерв под незавершённую операцию |

**Доступно** = подписка + купленные − резервы.

Пользователь видит одно число: «200 кредитов». Разделение по источникам нужно системе и админке.

## Порядок списания

1. Сначала кредиты подписки.
2. Затем купленные.

Отрицательный баланс невозможен. Списание атомарное (`lockForUpdate` строки счёта). Повтор с тем же `idempotency_key` не списывает повторно.

Чистый администратор (без роли «Подписчик») не тратит кредиты. Если у аккаунта есть роль подписчика — списание идёт как у обычного пользователя, даже при роли супер-админа.

## Начисление по тарифу

Поле тарифа: `subscribers_plans.credits_per_period`.

В начале нового периода подписки (регистрация, активация, продление, понижение в конце периода):

- `subscription_balance` становится равен пакету тарифа (остаток прошлого периода не складывается);
- купленные кредиты не меняются.

Переход на тариф выше:

- оставшиеся дни текущего периода пересчитываются в дни нового тарифа;
- к остатку кредитов подписки прибавляется пакет нового тарифа;
- купленные не меняются;
- кредиты тарифа при апгрейде складываются с остатком подписки; купленные не меняются.

Ключ периода: `subscription:{id}:period:{start_date}`.

## Стоимость одного кредита

Отдельная настройка в `credit_settings` (`rubles_per_credit`). Начальное значение сидера: **2 ₽**.

Это не стоимость AI-услуги и не константа в коде покупки.

- Админка: `/cw-page/credit-pricing`, блок «Стоимость одного кредита».
- Покупка считает `количество × текущая настройка`.
- Смена курса действует на новые покупки, уже купленные кредиты не переоцениваются.

## Стоимость AI-услуг

Каталог `credit_services` + тиры `credit_service_price_tiers`.

| code | Режим | Значение сидера |
|------|--------|-----------------|
| `generate_text` | фиксированная | 1 |
| `feedback_answer` | фиксированная | 1 |
| `generate_image` | по разрешению | default 5, 1K 10, 2K 15, 4K 15 |
| `edit_image` | по разрешению | те же |
| `generate_video` | за секунду × разрешение | 480p 4/сек, 720p 8/сек |

Разрешения не зашиты: админ добавляет строку (например 8K) без деплоя. Длительность видео — параметр операции, не строка каталога.

`CreditPriceCalculator::quote(code, params)` считает сумму для будущего списания инструментами. Неизвестный код или разрешение — ошибка, без нуля.

Стоимость **AI-анализа кабинета WB/Ozon** на этой странице есть отдельным блоком: ставки за 1000 входящих и 1000 исходящих токенов по провайдеру и модели (`ai_cabinet_analyzer_credit_tariffs`). Это не каталог `credit_services` и не цена шаблона промпта.

Сидер `CreditPricingSeeder` (внутри — и `AiCabinetAnalyzerCreditTariffSeeder`) идемпотентен: повторный запуск не создаёт дубли и не затирает правки админа. `credits_per_period` тарифов не трогает.

Сидеры запускаются только через artisan (`php artisan db:seed --class=CreditPricingSeeder`), не при открытии админки. Страница `/cw-page/credit-pricing` только читает и правит уже существующие строки.

Себестоимость провайдеров (`ai_request_logs`, `ai_costs`, `config/ai_pricing.php`) не связана с кредитами.

## Купленные кредиты

Покупка доступна в профиле и в модалке «Пополнить» в шапке панели.

1. Пользователь вводит количество.
2. Сумма = количество × `rubles_per_credit`.
3. Если на счёте хватает рублей — списание с кошелька + `CreditBillingService::addPurchased()`.
4. Если не хватает — в той же модалке открывается вкладка пополнения с недостающей суммой.

Маршрут: `POST /panel/credits/purchase`.

Купленные также появляются через корректировку администратора и разовый перенос остатка дополнительных AI-лимитов.

## Резерв (hold)

Для асинхронных операций (видео, ИИ-анализ кабинета):

- `reserve` уменьшает доступный остаток;
- `capture` списывает из резерва;
- `release` возвращает на те же источники.

Просроченные резервы снимает `credits:release-expired-holds` каждые 5 минут.

### AI-анализ кабинета WB / Ozon

Платится только генерация отчёта, не snapshot. Цена **динамическая**: по фактическим токенам ответа ИИ.

Ставки задаёт админ в `/cw-page/credit-pricing` (блок «ИИ-анализ кабинета»): провайдер, модель, кредитов за 1000 входящих токенов, кредитов за 1000 исходящих, коэффициент. Если точное имя модели не найдено — берётся ставка провайдера с пометкой «по умолчанию».

Формула (по каждому вызову ИИ, затем сумма):

```
raw = (input/1000 × ставка_входа + output/1000 × ставка_ответа) × коэффициент
credits = max(1, ceil(сумма raw))
```

1. При запуске / перегенерации backend оценивает объём snapshot и делает `reserve` с запасом 1.3. Если кредитов не хватает — генерация не стартует.
2. Когда job получил ответ ИИ, `AiCabinetAnalyzerCreditCalculator` считает фактическую сумму и `settleOpenHold` списывает её (лишний резерв возвращается; если факт больше резерва и на счёте хватает — добирает). Повторная отдача на фронт (`analysisPayload`) идемпотентна.
3. Повторный просмотр и повторный start уже готового анализа не списывают.
4. Если job окончательно падает — резерв возвращается.
5. Применённые ставки пишутся в `ai_cabinet_analyzer_credit_charges` и `billing_snapshot` анализа. Смена тарифа в админке старые анализы не пересчитывает.

Ключ идемпотентности: `{wb|oz}_ai_cabinet_analyzer:analysis:{id}:gen:{uuid}`.  
Пока анализ считается, в истории виден открытый резерв с пометкой «Зарезервировано». Как только ИИ вернул результат, резерв списывается — даже если пользователь не открывал отчёт.

Цена не принимается с frontend. Поле шаблона `credits_cost` больше не используется для списания.

### Ответы на отзывы Wildberries

Стоимость — каталог `credit_services.code = feedback_answer` (`CreditPriceCalculator::quote`). Не шаблон и не хардкод.

1. Ручная генерация (`POST /panel/wb/feedbacks/ai/generate`): проверка баланса → GPT → `spend` при успехе. Повторная генерация списывает снова.
2. Авто (`subscriber:wb-feedbacks-answer`): проверка баланса, списание только после успешного ответа в WB. Шаблонный бот не тарифицируется.
3. Нехватка кредитов — генерация не стартует (ручная) / подписка пропускается (авто). Старый `feedbacks_gpt_query` не используется.

Ключ: `feedback_answer:manual:{userId}:{uuid}` или `feedback_answer:auto:{cabinetId}:{reviewId}`.  
В истории: одна запись «Ответ на отзыв Wildberries». Служебные резерв/возврат в истории не показываются.

### AI Инструменты (текст, изображения, видео)

Стоимость — каталог `/cw-page/credit-pricing`: `generate_text`, `generate_image` / `edit_image` (по разрешению), `generate_video` (секунда × разрешение). С фронта сумма не принимается.

- Текст (`POST /panel/ai/marketplace`): проверка баланса → генерация → `spend` после успешного текста. Fallback Gemini→GPT списывает один раз.
- Изображение (`POST /panel/ai/image/start`): quote по `task_type` + `resolution` → генерация → `spend` после сохранения картинки. Fallback Grok — одно списание. Модерация и пустой ответ не списывают.
- Видео (`/panel/ai/video/start`, `/reference/start`, polling `/status/{id}`): `reserve` до вызова Grok; `capture` на первом успешном `done` после сохранения файла; `release` на ошибке, модерации, истечении и если файл не сохранился. Повторный poll и просмотр готового видео не списывают снова.

Ключи: `generate_text:user:{userId}:{uuid}`, `generate_image|edit_image:user:{userId}:{uuid}`, `generate_video:task:{uuid}` (колонка `ai_video_generation_tasks.credit_idempotency_key`).

Фронт получает таблицу стоимости в Inertia-пропе `pricing` и может уточнить через `POST /panel/ai/quote`. Старые `AI_TEXT_QUERY` / `AI_IMAGE_QUERY` / `AI_VIDEO_QUERY` инструмент больше не использует.

## История

Таблица `credit_ledger`: начисление, покупка, списание, резерв, возврат, корректировка, миграция.

В кабинете и админке:

- открытый `hold` показывается с пометкой **«Зарезервировано»**, чтобы было видно, куда ушли кредиты на время генерации;
- после списания (`capture` / `spend`) закрытый резерв скрывается — иначе одна операция выглядит как два списания;
- возврат резерва (`release`) остаётся в истории.

- Кабинет: `/panel/credits/history`
- Админка: вкладка «Кредиты» карточки подписчика

## Админка

- Тариф: «Кредиты за период» + лимиты кабинетов WB/Ozon и `repricer_nmid`.
- Подписчик: лимиты тарифа (кабинеты) + вкладка «Кредиты» (по тарифу / остаток / купленные / доступно / корректировка / полная история) и вкладка «Платежи и баланс» (рублёвые операции и списания кредитов).
- `/cw-page/credit-pricing` — стоимость 1 кредита, стоимость AI-услуг и ставки ИИ-анализа кабинета (токены Gemini/GPT). Старый `/cw-page/extra-limits` редиректит сюда.

## Кабинет

Shared props панели:

```json
{
  "credits": {
    "available": 200,
    "subscription": 120,
    "purchased": 80,
    "held": 0,
    "plan_per_period": 300
  },
  "rubles_per_credit": "2.00"
}
```

В шапке рядом с рублёвым балансом показывается доступный остаток кредитов (компактно, без увеличения блока). Кнопка «Пополнить» открывает модалку с вкладками «Счёт» и «Кредиты». Профиль и дашборд тоже показывают доступные кредиты.

Когда доступный остаток кредитов (и по тарифу, и купленные) доходит до нуля после списания или фиксации резерва, пользователь получает письмо «Кредиты закончились» — один раз за период тарифа. Если купленные кредиты ещё есть, письмо не уходит.

## Миграция старых остатков

Разовая Laravel-миграция `2026_08_18_180000_migrate_legacy_ai_limits_to_credits` (часть `php artisan migrate`). Отдельной artisan-команды нет.

Конвертируются только расходные AI-ключи: `feedbacks_gpt_query`, `ai_text_query`, `ai_image_query`, `ai_video_query`.

| Источник | Куда |
|----------|------|
| Остаток `limits_month` пользователя | `subscription_balance` (кредиты по тарифу) |
| Остаток `extra_limits_month` пользователя | `purchased_balance` (купленные) |
| месячный AI-пакет тарифа (`plans.limits_month`) | `credits_per_period` |

Курс берётся из каталога `/cw-page/credit-pricing` через `CreditPriceCalculator` (не хардкод): текст и ответ на отзыв — фиксированная цена; изображение — `default`; видео — 1 секунда `480p`. Суммы зависят от актуальных цен каталога.

Повторный прогон не начисляет снова (`credit_legacy_migrations`, `credit_legacy_plan_migrations`, ключи леджера). Если extra уже переносили старым способом, месяц всё равно переносится один раз.

История: «Перенос месячных лимитов в кредиты по тарифу» и «Перенос дополнительных лимитов в кредиты».

После переноса колонки `limits_month` / `extra_limits_month` / `extra_limits_plan` и таблица `extra_limits` удаляются миграцией `2026_08_18_200000_drop_legacy_ai_limit_columns`.
